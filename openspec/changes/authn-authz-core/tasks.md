- [ ] 2.11 Test-first: `NewJwtAuthenticator` requires `WithJwtVerifier`, builds the principal from the verified subject, takes the result ID from the token's own identifier, and joins a verification failure as `errors.Join(ErrAuthenticationFailed, err)` (decision 4, "Bearer tokens are authenticated by a verifier"); verify the configuration error, the happy path and that the cause remains matchable alongside the sentinel

## 4. session — record, store port, manager and stores

- [ ] 4.1 Test-first: session identifiers are 32 bytes from `crypto/rand` encoded base64url, and two managers never mint the same one ("Session identifiers are unguessable"); verify length, alphabet and that a stubbed reader failure is an error rather than a weak identifier
- [ ] 4.2 Test-first: the `Session` record carries the library-owned fields of decision 8 — identifiers, the four timestamps, `FirstFactor`, `MFA MFAState`, `PasswordChangePending`, the four external fields and `Data map[string]string` ("Challenge state is kept apart from consumer data"); verify the library never reads or writes `Data`, so no consumer key can forge or erase challenge state
- [ ] 4.3 Test-first: consumer `Data` is returned byte-for-byte unchanged through a store round trip ("Consumer data is returned unchanged"); verify with keys and values including Unicode, empty strings and characters that a typed map would coerce
- [ ] 4.4 Test-first: `NewManager` defaults to the in-memory store, a 30-minute idle timeout and a 12-hour absolute timeout, and refuses non-positive idle or absolute timeouts as configuration errors (departure a, decision 7) — a zero idle timeout expires every session on creation; verify the defaults and both configuration errors
- [ ] 4.5 Test-first: `Touch` moves the idle deadline to `now + idle`, capped at the absolute deadline ("Activity extends the idle deadline", "Sessions expire when idle and at an absolute limit"); verify with an injected clock that the cap holds near the absolute deadline
- [ ] 4.6 Test-first: `Load` enforces existence and expiry, returning `ErrSessionNotFound` and `ErrSessionExpired` distinctly ("Loading enforces existence and expiry"); verify both sentinels and that an expired session is never served
- [ ] 4.7 Test-first, red against an upserting save (departure b, decision 7): load a session, delete it, then `Touch` it — with an upsert-shaped `Save` the revoked session loads again; watch that resurrection happen, then split `Create` (insert) from `Save` (update-only, `ErrSessionNotFound` when missing) and verify the resurrection test now fails to resurrect ("Saving an existing session never re-creates a deleted one")
- [ ] 4.8 Test-first: `WithFirstFactor` and `WithExternalSession` apply before the single create write, so a crash cannot leave a live session without them ("The first factor is recorded in the creating write"); verify the store records exactly one write carrying both
- [ ] 4.9 Test-first: `Delete`, `DeleteByUser`, `DeleteExpired` and `CountActiveByUser` behave as decision 7 states ("Sessions can be deleted singly, per user and when expired"); verify counts returned and that deleting what does not exist is not an error
- [ ] 4.10 Test-first: `DeleteByExternalSession` and `DeleteByUserAndExternalIssuer` end federated sessions, and with an empty issuer — or an empty session identifier for the session-scoped delete — delete nothing and return no error ("Federated sessions can be ended by their provider session"); verify the empty-argument cases delete nothing
- [ ] 4.11 Test-first: the in-memory store copies records on write and on read behind a read-write mutex, so a caller mutating what it stored or loaded cannot reach the stored record ("An in-memory store is the default"); verify mutation through both directions leaves the store unchanged, under `-race`
- [ ] 4.12 Test-first: `Start(ctx)` runs `DeleteExpired` once per `WithHousekeepingInterval` (default 1 minute), `Stop()` ends it, both are idempotent, and the ticker exits when `ctx` ends (decision 9); verify with `testing/synctest` and the race detector, including double `Start` and double `Stop`
- [ ] 4.13 Test-first: without `Start`, expired sessions stay in memory but are never served, and the godoc says so (decision 9, stated limit); verify `Load` refuses them and that they remain until a purge
- [ ] 4.14 Test-first: `NewEncryptedStore` refuses a nil inner store or nil cipher, seals only `ExternalIDToken` with AAD `"scrty/session:external-id-token:" + ID` base64url-encoded, passes every other field through, and leaves an empty token unsealed (decision 10, "A sealing store protects the provider ID token at rest"); verify the sealed field, the untouched fields and the empty-token case
- [ ] 4.15 Test-first: the sealing store seals a copy so the caller keeps plaintext, reports an open failure as `ErrSessionUnreadable` distinctly from not-found, and never re-seals on load (decision 10) — a write on read is the resurrection race of decision 7; verify the caller's record still holds plaintext, the distinct sentinel under a retired key, and that `Load` issues no write

- [ ] 5.15 Test-first: `NewMFAPolicy` refuses a nil method lookup, allows an MFA-satisfied login and an exempt first factor, denies on a lookup error, challenges when enrolled on a different channel, and allows when not enrolled (decision 15, "Enrolled users are challenged for a second factor"); verify a table over the five outcomes

## 6. ratelimit — limiter, source keys and the guard

- [ ] 6.1 Test-first: the limiter counts failures rather than requests, and `Exceeded` reports without recording ("Limits count failures, not requests"); verify that repeated `Exceeded` calls never trip a limit on their own
- [ ] 6.2 Test-first: the window slides — a failure counts while strictly after `now - window` (decision 17, "The window slides"); verify the strict boundary with an injected clock, at the edge and one instant either side
- [ ] 6.3 Test-first: `NewMemoryLimiter` refuses a non-positive limit or window as configuration errors ("A limiter that cannot trip or always trips is refused at construction"); verify both
- [ ] 6.4 Test-first: a limiter error is treated as exceeded, so the guard fails closed ("Limiter errors fail closed"); verify the guard refuses when the limiter errors
- [ ] 6.5 Test-first: the in-memory limiter keeps at most `limit` stamps per key and prunes inline at most once per window, removing a key only when its newest stamp has expired ("The in-memory limiter bounds its own memory without disarming limits"); verify memory is bounded under sustained failures and that pruning never drops a key still inside its window
- [ ] 6.6 Test-first: the limiter WARNs once per replica on first use and says in its godoc that it is per replica ("The in-memory limiter is per replica and says so"); verify exactly one WARN across many calls
- [ ] 6.7 Test-first: `NewSourceKeyer` canonicalises sources — IPv4 per address, an IPv4-mapped address unmapped, IPv6 by its /64 prefix with the zone dropped, and `WithIPv6SourcePrefix` accepting 1..128 ("Sources are canonicalised before they become keys"); verify a table per address shape plus the prefix bounds
- [ ] 6.8 Test-first: empty, non-single-IP and unspecified addresses are refused with `ErrSourceUnattributable` under distinct log reasons, never pooled under a shared key ("Unattributable sources are refused, not pooled"); verify each refusal carries its own reason
- [ ] 6.9 Test-first: `SourceGuard.Check` refuses with `ErrThrottled` on the same key `RecordFailure` writes, and `RecordFailure` uses `context.WithoutCancel` and logs its errors rather than returning them ("Guards check before and record after, on the same key", "Any failed guarded attempt can be recorded"); verify the shared key and that recording survives a cancelled caller context
- [ ] 6.10 Test-first: `NewSourceGuard` refuses a missing limiter, and guards with different flow names keep separate counts unless deliberately given the same limiter and flow ("Guards refuse missing limiters and keep flows separate unless shared on purpose"); verify the configuration error and flow isolation
- [ ] 6.11 Test-first: throttle WARNs are sampled per flow and source, with `WithSourceGuardLogInterval` governing this guard alone (departure a, decision 17) — one refusal-log option must not govern both throttle logs and MFA logs ("Throttle refusal logs are sampled"); verify sampling per flow-and-source pair and that the interval is independent of the policy intervals
- [ ] 6.12 Test-first: the limiter and guard are safe for concurrent use, and the documented overshoot bound under concurrent bursts holds ("Limiters are safe for concurrent use"); verify under `-race` with `testing/synctest`, asserting the stated bound rather than exact counts

## 7. onetime — issuance, checking and consumption

- [ ] 7.1 Test-first: `NewManager` refuses an empty purpose and non-positive `WithTTL` or `WithIssuanceWindow`, defaulting to 15 minutes and 1 hour (departure a, decision 18); verify each configuration error and both defaults
- [ ] 7.2 Test-first: an issued token is `<id>.<base64url(32 random bytes)>`, bound to its purpose and subject, and two issues never collide ("Tokens are unguessable and bound to a purpose and subject"); verify the format, the entropy source and that the record identifier is a `pkg/id.ID` (departure a)
- [ ] 7.3 Test-first: the store holds `sha256(secret)` and, when bound, `sha256(binding)`, never the secret itself, compared in constant time ("Secrets are hashed at rest"); verify no stored field contains the presented secret and that comparison uses a constant-time primitive
- [ ] 7.4 Test-first: a token past its TTL is refused ("Tokens expire"); verify with an injected clock at the boundary and past it
- [ ] 7.5 Test-first: `Check` refuses a wrong purpose, a consumed token, an expired token, a binding mismatch and a secret mismatch all with `ErrInvalidToken`, refuses store errors the same way while logging at ERROR, and performs no writes ("Checking is uniform and has no side effects"); verify one table row per refusal and that the store records zero writes
- [ ] 7.6 Test-first: binding is optional — an unbound token checks without one, and a bound token refuses a wrong binding ("Binding is optional"); verify both directions
- [ ] 7.7 Test-first: `Consume` is a compare-and-set on `consumed_at IS NULL`, returning `ErrTokenNotFound` otherwise, so two racing consumers spend one token exactly once ("Consumption is atomic and follows a successful check"); verify under `-race` that exactly one of many concurrent consumers succeeds
- [ ] 7.8 Test-first: `Checked` values are obtainable only from `Check`, making check-then-consume structural rather than conventional (departure a, decision 18); verify a caller cannot construct a `Checked` outside the package
- [ ] 7.9 Test-first, red against spending on refusal: `Redeem` runs `Check`, then the caller's checks, then `Consume` — a caller check returning an error returns it unchanged and spends nothing, and a `Consume` failure returns `ErrInvalidToken` and no token ("A refusal between check and consume does not spend the token"); verify the token is still redeemable after a refused caller check
- [ ] 7.10 Test-first: `IssuedCount` counts issuance per subject over the manager's own window ("Issuance can be counted per subject over the manager's own window"); verify the count with an injected clock across the window boundary
- [ ] 7.11 Test-first: `PurgeExpired` takes its cutoff from the manager's own issuance window and a zero cutoff is refused, so a sweep cannot free quota `IssuedCount` still counts nor break a live token ("Purging cannot free issuance quota or break live tokens"); verify quota survives a purge and that live tokens still redeem, plus `ErrReapUnsupported` where no reaper exists
- [ ] 7.12 Test-first: the in-memory store copies records in and out so a caller cannot reach a stored record ("The in-memory store isolates stored records"); verify mutation through both directions leaves the store unchanged, under `-race`

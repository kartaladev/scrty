# Tasks

Every task follows the project's test-first rule: write the failing test, run it, confirm it fails
for the intended reason (a compile error is not a red step), then implement. "Verify" in a task
names the focused run that must first fail and then pass. Table tests follow the `table-test`
skill, test doubles the `use-mockgen` skill, and PostgreSQL tests the `use-testcontainers` skill
through `test.RunTestPostgres`. Each group ends with a `/simplify` pass on the code it touched and
a re-run of its tests.

Two claims in `design.md` are `UNREPRODUCED` (the password-change gate refuses logout; the
verify endpoint's `mfa` errors map to 500) and one is a hypothesis about code not yet written (the
two-session race). Group 6 adds two more `UNREPRODUCED` claims, both in decision 10: the sealing
wrapper passes the emailed code through unsealed (task 6.4), and a zero generation matches an
enrolment stored without one on a durable store (tasks 6.3–6.6). The task that addresses each starts with its reproducing test. If that test
passes on the unchanged code, the claim was wrong: stop, report it, and the main session removes
the departure from `design.md` instead of implementing it.

Groups 1 to 5 need nothing from other active changes. Group 6 starts only after
`durable-persistence` is archived.

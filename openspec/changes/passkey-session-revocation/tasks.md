# Tasks

Every task is test-first: write the failing test, run it and see it fail for the intended reason
(a compile error is not a red step), make it pass, then refactor. Each task names how it is
verified. A signature change owns every caller of the changed API across the workspace
(`_test.go` files, `httpsec`, the `test` module, Examples and README snippets), so the workspace
compiles and passes at the end of every task group. Section names in parentheses are the spec
requirements the task covers.

Verify with `go test -race ./session/...` and `go build ./...` in every module
- [ ] 1.2 The shared session suite in the `test` module gains the except-one cases: the count returned, another user's kept session untouched, a kept identifier naming no session, and an expired kept session left in place; the in-memory store passes it (D6). Verify with `go test -race ./...` in `test/storetest` (or the package holding the session suite)
- [ ] 1.3 Durable stores: `internal/pgschema` statement `DELETE FROM sessions WHERE user_id = $1 AND id_digest <> $2` with the kept identifier digested as `Delete` digests it, and `DeleteByUserExcept` on the `sqlstore`, `pgx` and `gorm` session stores joining an ambient transaction; the shared suite and a rolled-back ambient-transaction case pass on every backend (D1, D6). Verify with `go test -race -run 'Session' ./sqlstore/ ./pgxstore/ ./gormstore/` in the `test` module (needs Docker) and `go test -race ./...` in `gorm` and `pgx`

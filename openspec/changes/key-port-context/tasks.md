Every task is test-first: write the failing test, run it, confirm it fails for the intended reason (a compile error is not a red step), make the smallest change that turns it green, then refactor. Paths are the ones on `main` after `reauthentication` merged. Where a task rewrites an existing test that pins the behaviour it changes, it says so: that rewrite is deliberate, not a weakened test.
